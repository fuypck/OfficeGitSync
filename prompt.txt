OfficeGitSync Rust 版产品需求与设计原则

项目定位
面向普通办公用户的本地文档版本备份工具。重点解决工作文档防丢和历史回溯。为纯文本提供按行差异，为 Office 等二进制文档保存完整版本。

Rust 预览构建与正式发布状态以 GitHub Actions 和 Releases 为准。

已实现功能
- Windows 和 Linux 简体中文桌面应用，提供「文档备份」「历史版本」「设置」「Git 高级」四页。
- 用户可打开或初始化工作目录。Windows 支持原生工作目录和导出目录选择器，两个平台都可手动输入。
- 递归监听文件变化，防抖后只列出相应 Git 变更。支持手动扫描、勾选提交、取消本轮备份、编辑时间预填说明，以及创建可选标签。
- 浏览当前分支和旧版时间线的历史。支持标签和安全导出，记住上次成功导出的目标目录。
- 支持系统托盘、关窗行为、静默启动、当前用户登录启动及重复打开时唤醒既有实例。Linux 托盘依赖桌面托盘服务。
- 支持系统、浅色和深色主题，按软件管理排除规则，保留自定义规则，兼容旧配置导入，提供默认关闭的备份和监听日志。
- 提供文本差异、添加 Remote 和用户主动 Fetch。常规本地 Git 操作使用内置 libgit2。

设计原则
- 低打扰监听，用户明确确认后才提交。以选定路径为提交范围，检查分支、暂存区、索引锁及仓库操作状态。遇到未知或不安全的情况，明确提示并停止。
- 文档保全优先。历史版本导出到工作区外的新子目录，保留原文件和 Git 历史。避免覆盖已有标签、恢复目标及用户暂存内容。
- 保持工作目录整洁。Git 元数据位于工作目录，其他配置、日志和实例信息放入当前用户配置目录。配置写入应可恢复，保留损坏的旧文件以便排查。
- 核心内置，能离线使用。Linux 图形会话、系统字体和桌面托盘由系统提供。错误应通过简体中文界面提示，可选日志记录关键事件。
- 普通用户从备份和历史页面完成日常工作。配置集中在设置页，Git 专用操作集中在高级页。

未来规划
- Linux 原生目录选择器与分发包，进一步验证 Windows 文件监听与各桌面环境的托盘兼容性。
- 更完整的远程凭据支持。Push、Pull 和同步应经由明确的用户设置或操作。
- 探索 Office 文档语义差异。原地恢复或历史删除须先明确安全边界、恢复策略及用户授权要求。
